# UCAgent 阶段进展简报（2026年7月14日—7月16日下午）

## 项目目标

UCAgent 面向芯片验证任务，目标是让大模型 Agent 自动理解待测设计、编写验证环境和测试，并根据测试反馈持续修复。当前研究重点不是单纯增加 Prompt，而是建立一套跨 DUT 的修复经验复用机制：把历史运行中的“失败—修改—验证结果”整理成策略，在新 DUT 遇到相似问题时提供可靠参考，同时避免错误经验干扰 Agent。

## 本阶段完成的工作

### 1. 建立可信的测试结果判定与实验基线

修复了原有测试摘要可能把“未运行测试”或进程异常误判为成功的问题，将结果明确区分为正常通过、测试失败、基础设施错误、超时、崩溃和未收集到测试六类，并增加了解析单元测试。随后对旧策略库进行审计：旧版 75 个 Episode 中发现 12 个建立在无效测试结果之上；清理、去重和质量筛选后，形成当前在线使用的 v1 策略库，共保留 39 条运行时策略。这一步保证策略库不会继续把无效修改当成成功经验，并冻结了可复现实验快照。

### 2. 将“成功后的一串操作”升级为可解释的修复归因

原方法只要在一次失败后看到成功，就把中间修改视为有效修复，容易把无关操作一起写入策略库。本阶段实现了 Episode Credit v2：每个修复片段记录失败前状态、修改序列、验证后状态、失败集合变化、是否引入回归、信息增益、操作成本、作用类型和置信度，并区分有效推进、诊断、无进展、回归和无效执行五类。基于 4 个 DUT、8 次运行生成了 424 个候选 Episode，其中 73 个暂定为可复用项。

为避免只用程序自我证明，进一步对 40 条平衡样本进行了独立盲标。当前规则归因准确率为 80.0%，Macro-F1 为 79.76%；诊断和无效执行识别达到 100%，但“进展/回归/无进展”仍容易受测试范围变化影响。该结果低于预设的 90% 上线门槛，因此 v2 目前只作为离线研究候选，没有注入正在运行的 Agent。这既验证了方向可行，也暴露了下一步需要解决的核心问题。

### 3. 通过 Adder 回归发现并修复跨阶段负迁移

最新 Adder 实验在 Stage 20（创建测试模板）停留约 2 小时 22 分钟。分析发现不是单纯的模型随机性：该阶段本应保留“Not implemented”占位测试，但 Checker、Prompt 错误摘要和策略检索给出了互相矛盾的指令，并错误检索到 Stage 21“实现测试并使其通过”的经验，导致 Agent 在“保留模板”和“实现测试”之间反复修改，累计产生 192 次模型请求和约 658 万输入 Token。

目前已完成三项修复：统一模板 Checker 与测试退出码的契约；使 Prompt v1 的错误摘要感知当前阶段；为策略 Episode 和压缩提示增加阶段角色硬门控，禁止“模板生成”与“测试实现”策略混用。针对性回归测试 38 项全部通过，并冻结了新的 Adder 实验候选版本。

## 当前结论与下一步

目前已经从“能生成并注入历史经验”的工程原型，推进到“能识别无效证据、评价修复贡献并控制负迁移”的研究雏形。但尚不能宣称策略库已经缩短整体 DUT 验证时间：v2 归因准确率未达到上线标准，修复后的 Adder 也仍需重新实测。

下一步优先完成两项实验：第一，重新运行 Adder，重点比较 Stage 20 的通过率、重复失败次数、模型调用数、Token 和耗时，验证本次修复是否真正消除循环；第二，改进 v2 对“单测试与整文件测试”范围变化的比较规则及回归判定，再进行第二轮独立标注，达到 90% 门槛后才进入在线 A/B 测试。之后采用跨 DUT 留一验证和多随机种子实验，评价策略库是否具备可泛化的效率收益。
